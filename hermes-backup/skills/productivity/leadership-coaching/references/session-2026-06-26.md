## Key Pattern: Async Telegram Session

**Problem:** The "one question at a time, wait for answer" rule only applies to manual in-chat sessions. In cron, the job fires once and exits — you cannot wait between questions.

**Solution:** Send all questions in one execution run. Then rely on Ratul's Telegram replies coming back asynchronously. When he replies, the NEXT cron job (or a manual follow-up) picks up the answers and delivers feedback.

**State management:** The session file at `/Users/ratul/Documents/leadership_conversation/{YYYY-MM-DD}.md` carries the full session state (questions, placeholder for answers, feedback framework). When answers arrive, update that file and deliver feedback via `hermes send`.

**Tracking:** The `/tmp/leadership-coaching-last-topics.txt` must be updated BEFORE sending questions (so if the job crashes mid-send, the topic is already marked as used).
